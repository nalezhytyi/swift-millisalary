# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Millisalary, the app that shows your salary being earned in real time, rewritten natively in Swift for macOS. It replaces the Electron + React app in `../electron-millisalary` (~273 MB, most of it the Electron framework, and most of its UI work went into faking macOS controls in CSS). That app's `CLAUDE.md` is the behaviour spec: what isn't ported yet is described there. Treat `../electron-millisalary` as a read-only reference: never edit, build or commit there (reading it, or bundling its TypeScript into a temporary folder as the parity script does, is fine).

The user writes in Ukrainian: answer in Ukrainian. Code, comments, commit messages and this file stay in English.

## Commands

```bash
xcodegen generate                       # (re)generate Millisalary.xcodeproj from project.yml; after adding files too
xcodebuild -project Millisalary.xcodeproj -scheme Millisalary -derivedDataPath build/DerivedData build
xcodebuild -project Millisalary.xcodeproj -scheme Millisalary -derivedDataPath build/DerivedData test
swift test --package-path Packages/MillisalaryCore   # the same tests without Xcode, in seconds
open build/DerivedData/Build/Products/Debug/Millisalary.app
scripts/parity/generate-fixtures.sh     # regenerate the parity fixture from the Electron app's TypeScript
```

- XcodeGen (`brew install xcodegen`, 2.46) is required: `Millisalary.xcodeproj` and `Millisalary/Info.plist` are generated and gitignored, `project.yml` is the source of truth (build settings, Info.plist keys, the package dependency, the scheme). Files in `Millisalary/` are picked up by folder, but only after `xcodegen generate`.
- Release: `-configuration Release`; the app is in `build/DerivedData/Build/Products/Release/` (~1.9 MB, the face image is 140 KB of it). There is no packaging or release script yet.
- Commit with the repo-local git identity (`nalezhytyi`, set in `.git/config`), not the global work identity. Conventional Commits with a lowercase scope, e.g. `feat(tray): …`, `feat(windows): …`, `fix(core): …`.
- There is no remote. Never create a GitHub repository, add a remote or push without the user's explicit approval for that specific action.

## Structure

- `Packages/MillisalaryCore/` — a local Swift package with everything that doesn't need AppKit or SwiftUI: the earnings model, settings schema, validation and edits, money formatting, the menu bar's text. Pure and unit-tested; the app depends on it (`packages:` in `project.yml`), and the scheme's test action runs its tests.
  - `Earnings.swift` — `EarningsModel` (`calculations.ts`): `earnings(at:_:)`, `workingWindow(on:_:)`, `isScheduledDay(_:workingDays:)`, `paydayInMonth(of:payday:)`, `nextPayday(from:payday:)`, plus `Period` (with `label`, "This hour" … "This year", the menu bar's and Breakdown's names), `EarningsSettings`, `WorkdaySettings`, `EarningsSnapshot`.
  - `Settings.swift` — `Settings` (`settings.ts`): the same 15 keys, values and defaults as the Electron app's `settings.json`; `Settings(sanitizing:)` / `applying(_:)` / `apply(_:for:)` are `sanitizeSettings` / `sanitizePatch` / one validator, `propertyList` is the way back, `workday` / `earningsSettings(exchangeRate:)` feed the model.
  - `SettingsEditing.swift` — the settings pane's edits with the coupled schedule fields (`settingsDraft.ts` and the `getNext*` helpers): `setStartHour` moves End by hours a day, `setEndHour` recomputes hours a day (an End before Start pulls Start back to it, and with no time between them hours a day fall back to 8, as in the Electron app), `setWorkingHoursPerDay` moves End, `setWorkingDays` / `setPayday` normalize.
  - `SalaryForm.swift` — `normalizeWorkingDays`, `normalizePayday`, `normalizeWorkingHoursPerDay`, `endHour(from:workingHoursPerDay:)` (`getEndHourFromStart`), `workingHoursPerDay(from:to:)` (`calculateWorkingHoursPerDayValue`) and the defaults (8 hours, 22 days).
  - `TimeOfDay.swift` — a wall-clock time; `TimeOfDay(parsing:)` / `formatted` are `parseTimeInputValue` / `formatTimeInputValue` for the `"HH:mm"` strings the settings keep.
  - `CurrencyFormat.swift` — `formatCurrency` (`uk_UA`, narrow symbol, plain spaces: `54 321,00 ₴`) and `formatCurrencyParts` (from the attributed format's number parts).
  - `MenuBarContent.swift` — the menu bar title and amount rows (`getTitle` / `getAmountLabels` in `tray.ts`).
  - `ExchangeRate.swift` — `CurrencyPair` (`key` "USD>UAH", `Settings.ratePair`), `ExchangeRateAPI` (the URL, the response's rate with `fetchRate`'s checks, the 6 h refresh and the 1 min … 30 min retry delays) and `sanitizeRates` for the cached rates.
- `Millisalary/` — the app target (Swift 6, default actor isolation `MainActor`).
  - `MillisalaryApp.swift` — the SwiftUI `App`: the main `Window` scene, the menu commands (`AppCommands`) and `AppDelegate` (Dock reopen, no quit on the last window).
  - `AppController.swift` — owns the store, `Navigation`, `Ticker` and the status item; `show(_ pane:)` / `showPeriod(_:)` are what every menu, the menu bar item and the Dock call (`showSection` in the Electron app). Applies the theme (`NSApp.appearance`) and runs the Electron import at launch.
  - `Navigation.swift` — `Pane` (earnings, breakdown, settings: window state, not a setting), `SidebarItem` (titles and SF Symbols), `Navigation` (`pane`, the split view's column visibility).
  - `SettingsStore.swift` — `@Observable`, one `UserDefaults.standard` value per settings key, always read through `Settings(sanitizing:)`; KVO on the keys picks up changes from anywhere, `defaults write` in Terminal included. `update(_:)` is `applySettingsPatch`: only the fields an edit changed, each through its validator (a rejected value keeps the stored one), and only those are written.
  - `ElectronSettingsImport.swift` — the one-time import, see Decisions.
  - `ExchangeRateStore.swift` — `@Observable`, the rate for the pair the settings name (see Exchange rate); `AppController` points it at `store.settings.ratePair` and refreshes it on wake.
  - `Settings+App.swift` — `AmountDisplay` (currency and rate) from `amountDisplay(_ rates:)`, and `earnings(at:_:)`: every amount on screen goes through these two.
  - `Ticker.swift` — `now`, every 100 ms while running; `Views/TickWhileVisible.swift` runs it only while the window's occlusion state says it's visible (not closed, minimised or covered).
  - `StatusItemController.swift` — the menu bar item, see below.
  - `Views/` — `MainView` (the `NavigationSplitView` and its sidebar), `EarningsView` (the dial, the stats row, the setup hint), `BreakdownView`, `SettingsView`.
  - `Clock.swift`, `DebugDump.swift` — Debug-only test hooks (Testing).
- `scripts/parity/` — `fixtures.ts` and `generate-fixtures.sh`, which write `Packages/MillisalaryCore/Tests/MillisalaryCoreTests/Fixtures/parity.json`.

## The port and its parity

The Swift core must give the Electron app's results, so the TypeScript is the oracle. `generate-fixtures.sh` bundles `fixtures.ts` with the esbuild in `../electron-millisalary/node_modules/.pnpm/esbuild@*/` (aliasing `@shared` and `@renderer` to its `src/shared` and `src/renderer/src`, resolving `dayjs` from its `node_modules`) into a temporary folder and runs it with node. The fixture holds 2610 `calculateEarnings` / `getWorkingWindow` / `isScheduledDay` results (15 schedules: overnight, no end time, same start and end, fractional hours and days, 24-hour days, a rate, no salary; at edge instants plus 20 seeded random ones over 2026–2028; in Europe/Kyiv, America/New_York and Asia/Kolkata), every payday 1–31 for 13 months, 256 `formatCurrency` and 256 `formatCurrencyParts` results (8 currencies, 2 and 4 digits, half-way amounts), 174 coupled-field edits (`withStartHour` / `withEndHour` / `withWorkingHoursPerDay` / `withWorkingDays` / `withPayday` on 6 schedules, times anchored to a day without a DST change), the normalizers (NaN and the infinities included), time strings and 22 raw settings objects through `sanitizeSettings`. `ParityTests.swift` compares money **exactly**, not with a tolerance. The fixture is committed, so the tests don't need node; regenerate it only when the reference changes, and keep the edge cases.

What makes the results equal to the bit, keep it when changing the core:

- Times are whole milliseconds as `Double`, like a JS `Date` (`epochMilliseconds`); `earnings(at:)` rounds `now` to a millisecond first. The arithmetic runs in the TypeScript's order (`millisecondSalary * 3600 * 1000`, not `* 3_600_000`).
- Each dayjs call maps to a `Calendar` call in the model's calendar (its time zone stands in for the local one): `startOf('day' | 'month' | 'hour')`, `add(n, 'day')` keeps the wall-clock time, `day()` is 0 for Sunday, `diff(…, 'day')` corrects for a change of UTC offset and truncates.
- `atMinutes` mirrors `startOf('day').hour(h).minute(m)`: the hour can run past 23 into the next day (a missing end time is start + hours/day, e.g. 20:00 + 9.5 h is 05:30 next morning) and fractional minutes are truncated (09:00 + 8.33 h ends at 17:19, not 17:19:48). When the end isn't after the start, the end is start + hours/day in milliseconds, truncated like a JS `Date`. `endHour(from:)` adds the same truncated milliseconds.
- `workingDays` is a `Double` and stays fractional (the Electron validator doesn't round it); `payday` is an `Int` (it does).
- `formatCurrency` rounds half away from zero (`.toNearestOrAwayFromZero`), as `Intl.NumberFormat` does; Foundation's default is half-even. Both format the shortest decimal of the double, so `1.005` gives `1,01`.
- The validators treat an `NSNumber` boolean as not a number and a number as not a boolean (`CFBooleanGetTypeID`), like `typeof`.
- Read JSON numbers with `JSONDecoder`, not `JSONSerialization`: the latter returns long decimals as `NSDecimalNumber`, whose `doubleValue` is off in the last bits (it broke the first test run). The Electron import has to take untyped JSON for the validator, so it converts any `NSDecimalNumber` through its exact text.
- Not covered: a start or end time inside a DST gap or overlap (03:00–04:00 in Kyiv on the last Sundays of March and October). JS moves a missing local time forward and picks the first of a repeated one; `Calendar` may differ. Those are Sundays, which aren't paid, so only `rates` could differ. The coupled fields are wall-clock in Swift, where the Electron app adds hours to a `Date` of today, so on a DST day its End could come out an hour off; the Swift one doesn't.

## Decisions

Taken on 2026-10-31 and 2026-11-01; "the user's choice" marks what the user picked between options.

- **XcodeGen** over a hand-made `.xcodeproj` or SwiftPM with a bundling script (the user's choice): a readable, diffable spec that `xcodebuild` builds, with asset catalogs, Info.plist keys and SPM dependencies (Sparkle later) handled by Xcode.
- **macOS 14** deployment target (the user's choice): `@Observable`, `SettingsLink`, `SMAppService`, `MenuBarExtra`, `@Environment` with observable types. Newer APIs (Liquid Glass, `glassEffect`, `toolbarBackgroundVisibility`, macOS 15/26) go behind `if #available`; on newer systems the native look comes by itself. Built with Xcode 27.2 / macOS 27.2 SDK / Swift 6.4.
- **Swift Testing** for tests. Swift 6 language mode; the app target uses `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` and approachable concurrency, so app code is main-actor by default (`DefaultsObserver` opts out with `nonisolated`). The core's `Settings` clashes with SwiftUI's `Settings` scene: write `MillisalaryCore.Settings` in SwiftUI files.
- **Bundle IDs**: Release is `com.nalezhytyi.millisalary`, the Electron app's, so the native app is its successor (same login item and notification identity, installs over it). Debug is `com.nalezhytyi.millisalary.debug`, so a dev build never shares settings, notifications or the login item with an installed copy.
- **Signing**: ad hoc (`CODE_SIGN_IDENTITY = -`) with the hardened runtime, not notarized; there is no Developer ID. Not sandboxed, like the Electron app (no App Store, and a sandbox would keep the app from reading the Electron app's `settings.json`).
- **Settings in UserDefaults**, one value per key under the `settings.json` names, rather than a JSON file: native, inspectable with `defaults read`, editable with `defaults write`. Everything read goes through the ported validator, every edit through `SettingsStore.update`.
- **The main window is a SwiftUI `Window` scene**, not an AppKit `NSWindow` hosting SwiftUI. The hosted version was built first and dropped the same day: with `NSHostingController` (even with `sceneBridgingOptions = .all`) the `NavigationSplitView` got no toolbar, no sidebar button and no navigation title, and the sidebar drew the old flat way. In a `Window` scene macOS 27 draws it natively: the title is the selected row's name, the sidebar button is the glass circle next to the traffic lights. The cost: AppKit code can't open a scene, so `AppCommands` hands its `@Environment(\.openWindow)` to `AppController.openWindow` while the commands are built (at launch, window open or not), and `show(_:)` calls it, which opens the window or brings it to the front. Closing the window closes it (SwiftUI keeps the `NSWindow` and reuses it), unlike the Electron app's hide-on-close: a native window is cheap to bring back, and nothing ticks while it's closed. `NSWindow.allowsAutomaticWindowTabbing = false`: one window, no tab items in the menus.
- **Always in the Dock** (the user's choice), like the Electron app: closing the window leaves the app in the Dock and the menu bar; a Dock click or a second launch reopens it (`applicationShouldHandleReopen`). `showInMenuBar` hides the menu bar item (`isVisible`).
- **Settings shows only what works** (the user's choice): Salary (amount, salary and display currency), Schedule, Payday, Menu bar, Appearance. Open at login and the notifications come with their features. Native controls throughout (a grouped `Form`, `Picker` pop-ups with the current value added when it isn't a choice, e.g. 8.33 hours, `DatePicker` hour-and-minute fields on a fixed day without DST, a `TextField` with a number format that commits on Return or when focus leaves, as native fields do, rather than on every keystroke like the Electron one).
- **The static face** in the dial and the payday card until the animated one (the user's choice): `MoneyFace` in the asset catalog is the Electron app's `money-face.png`.
- **The Electron settings are imported automatically** (the user's choice), once: on the first launch, if nothing is stored here yet, from the newest of `~/Library/Application Support/{Millisalary,electron-millisalary}/settings.json`, through the validator, with its cached `exchangeRates` (through `sanitizeRates`; rates already known here win); the file is only read. `didImportElectronSettings` in the defaults marks the attempt, whether or not there was a file.
- **NSStatusItem**, not SwiftUI's `MenuBarExtra`: the title needs `monospacedDigitSystemFont` (like Electron's `fontType: 'monospacedDigit'`), and an AppKit menu can update its rows while open (the timer runs in the run loop's common modes, so the amounts tick inside the open menu, which the Electron app couldn't do: it only rebuilt its menu while closed).
- **Until a pair's rate is known, amounts stay in the salary's currency** (rate 1, the salary currency's symbol), e.g. on a first launch without network; Breakdown's footer says so. The Electron app multiplied by 1 and showed the display currency's symbol meanwhile, which put wrong numbers on screen.
- Small deliberate differences from the Electron app: amounts tick in monospaced digits in the dial, the stats row and Breakdown (no jitter at 10 updates a second); the payday date and the number pickers follow the system's region format (e.g. "Tuesday, 10 November" on an en_UA Mac, where dayjs always wrote "Tuesday, November 10"); the setup hint's button says "Open Settings" (title case, as macOS buttons do).

## Main window

One `Window` (820×580 by default, at least 520×460, its frame kept by SwiftUI) with a `NavigationSplitView` (sidebar 180–360 pt, 240 by default). The sidebar has an Earnings section with This Hour, Today, This Week, This Month and This Year, then Breakdown and Settings, each with an SF Symbol. Picking a period sets the `selectedPeriod` setting and shows the Earnings pane; the pane itself is window state (`Navigation.pane`). The navigation title is the selected row's name.

- **Earnings**: the dial (the Electron SVG's proportions: a ring of radius 44 and stroke 6 in 100, the track in `.quaternary`, the arc in the accent colour from the top, grown in over 0.7 s when it appears and when the period changes, the 100 ms ticks applied directly in between, nothing under Reduce Motion), the face at 16% of its width, the amount with its last two of four decimals at 62% in the secondary colour and the symbol at 70% in the accent colour, sized to fit like the Electron app's estimate, and "of <total> <today/this week/…>"; under it the stats row (Today, This week, This month) or, with no salary, the setup hint with a button to Settings. Its toolbar has no background (`toolbarBackground(.hidden)`), since nothing scrolls under it there.
- **Breakdown**: a grouped `Form`: the next payday card (face, date, paycheck, days left), Earned so far (each period's amount, total and a progress bar), Your rate (per second with four decimals, minute, hour, day) and its footer, which adds "Exchange rate: 1 USD = 45,4 UAH." when the currencies differ, or that amounts are in the salary currency until the rate arrives.
- **Settings**: see Decisions; every change applies at once.
- The `Ticker` drives both live panes at 100 ms; only views that read `ticker.now` redraw.

The app menu (`AppCommands`): Settings… ⌘, in the app menu; in View, Toggle Sidebar ⌃⌘S, This Hour … This Year ⌘1–⌘5 as checkmarked items that follow the selected period, and Breakdown ⌘I. The rest is SwiftUI's and AppKit's standard (Edit, Window with the window listed, Help). Check for Updates… comes with the updater.

## Exchange rate

`ExchangeRateStore` (exchangeRate.ts in the Electron app). `follow(pair)` runs at launch and whenever a currency changes (an `withObservationTracking` loop in `AppController`; other setting changes don't refetch): the same currency is always 1; otherwise the cached rate for the pair at once (nil when there is none) and a fetch of `https://api.exchangerate-api.com/v4/latest/<FROM>` with `URLSession`, whose `rates[<TO>]` must be a finite number above 0, and a non-2xx status is a failure too. One `Task` per pair loops: after a fresh rate it sleeps 6 h, after a failure 1 min, doubling up to 30 min; following another pair cancels it, and a result for a pair no longer followed is dropped. `refresh()` on `NSWorkspace.didWakeNotification` fetches again at once. Each fresh rate is cached in the defaults as `exchangeRates`, a dictionary of `Double`s keyed like "USD>UAH" (read through `sanitizeRates`), so an offline launch keeps converting. `rate(for:)` only returns the followed pair's rate. Fetches and failures are logged under the `exchange-rate` category of the bundle ID's subsystem (no amounts, only pairs and rates).

## Menu bar item

`StatusItemController` shows the template icon (`MenuBarIcon` in `Assets.xcassets`, the Electron app's `trayTemplate.png` / `@2x`, 16 pt) with the amount as the button title in monospaced digits, refreshed by a 1 s timer (0.1 s tolerance) and immediately when the settings change (`withObservationTracking`). Before a salary is set it shows the icon alone. The menu lists This hour / Today / This week / This month / This year with their amounts (each opens Breakdown), a separator, Open Millisalary, Settings…, a separator and Quit Millisalary (⌘Q); without a salary the amount rows and their separator are left out. Titles and rows are only touched when their text changed, the menu is only rebuilt when the number of rows changes. `showInMenuBar` off hides the item.

## Testing

- `swift test --package-path Packages/MillisalaryCore` runs the parity and unit tests (23, under a second); `xcodebuild … test` runs the same through the scheme. There are no UI tests: the app is checked by running it.
- The dev build keeps its settings in the `com.nalezhytyi.millisalary.debug` domain. On its first launch it imports the Electron app's settings (the user's real salary): don't quote those amounts back. `defaults write com.nalezhytyi.millisalary.debug monthlySalary -float 54321` (and `menuBarAmount selected`, `selectedPeriod year`, `theme light`, …) changes a running app within a second; `defaults delete com.nalezhytyi.millisalary.debug` resets it, `defaults delete com.nalezhytyi.millisalary.debug didImportElectronSettings` together with the settings keys makes the next launch import again. Put back what you changed when you're done.
- Debug-only launch arguments (read through the UserDefaults argument domain, compiled out of Release):
  - `-debugNow "2026-10-29 13:30"` starts the clock at that local time and lets it run, so a weekend can show a weekday ticking (weekends earn nothing). It's a date and not an offset because a negative offset (`-debugTimeShift -205200`, tried first) was ignored: a value starting with `-` reads as another flag.
  - `-debugPane earnings|breakdown|settings` opens the window on that pane.
  - `-debugDumpMenus <path>` writes the app menu and the menu bar item's menu as text a second after launch (titles, shortcuts, `[on]`, `[disabled]`, `[hidden]`). The status menu's rows carry amounts.
  - `-debugStatusItemSnapshot <path.png>` draws the menu bar button into a PNG on every title change.
  - `-debugExchangeRateURL <base>` sends the rate requests elsewhere; `http://127.0.0.1:9/` (nothing listens) shows the offline behaviour and the retries.
- The rate's log: `/usr/bin/log stream --level info --predicate 'subsystem == "com.nalezhytyi.millisalary.debug" AND category == "exchange-rate"'` (in zsh a bare `log` is a builtin). To seed the cache, write real numbers: `defaults write … exchangeRates '{ "USD>UAH" = 41.5; }'` stores the rate as a string, which `sanitizeRates` rightly drops; set it through `UserDefaults(suiteName:)` from a few lines of Swift instead.
- Seeing what's below the fold: neither `NSWindow Frame main` in the defaults nor a bigger `defaultSize` changed the window's 580 pt height at launch, but a temporary `.defaultScrollAnchor(.bottom)` on a pane's `Form` opens it scrolled to the end (used for Breakdown's footer on 2026-11-01, then removed). Revert such temporary edits with an edit, not `git checkout`, which also throws away the uncommitted work in the file.
- Screenshots: `screencapture` works here without a prompt, Accessibility (System Events, synthetic clicks and keys) is not granted, so nothing can be clicked or typed from the shell. The main window is captured on its own with `screencapture -x -o -l<id>`, the id being the largest on-screen layer-0 window of the app's pid in `CGWindowListCopyWindowInfo` (a few lines of Swift run with `swift`). To check that amounts tick, capture twice a second apart on a faked weekday and compare the same crop.
- The menu bar item: on a Mac with a notch, macOS 27 hides status items that don't fit right of the notch behind a `«` overflow, and this Mac's menu bar is full, so the item is hidden as soon as it has a title (even a high `NSStatusItem Preferred Position` didn't bring it out); hence the snapshot argument. Its PNG is white text on transparent in a dark menu bar: composite it on a dark colour to look at it. Its menu can only be checked by clicking it, or as text through `-debugDumpMenus`.
- Closing the window and reopening it can be checked without clicks: close it from a temporary Debug hook (`performClose` on the visible titled windows a few seconds after launch), then `open` the app again without `-n`, which sends the reopen event a Dock click sends. Done on 2026-11-01: the window came back and ticked again. Remove the hook afterwards.
- Checked by running on 2026-11-01: a live USD>UAH rate converts everything and shows in Breakdown's footer; switching the display currency to EUR and back while running fetches each pair; with the API unreachable, no cache keeps amounts in USD with the footer's note and logs a retry in 60 s, and a cached rate still converts.
- Not checked by running so far: editing in Settings (needs clicks; the coupled fields themselves are parity-tested), the sidebar button and ⌃⌘S, the menu bar item's menu items, the refresh on wake (needs the Mac to sleep) and the 6 h refresh.

## Not ported yet

In the Electron app's `CLAUDE.md`: the end-of-day and payday notifications (`shared/notifications.ts`; natively UserNotifications scheduled ahead), the login item (`SMAppService`) with the start-at-login detection and a hidden window, the update check (GitHub releases; Sparkle is the usual native updater) and its menu items, Amplitude analytics (a native Swift SDK exists; whether Session Replay works for native macOS apps is unverified, and every amount on screen must be masked if it's used), the app icon (the Dock shows the generic one) and the animated money face (`public/images/money-face.webp`, 150 frames at 20 ms) with the launch splash, and packaging (dmg, release script).
